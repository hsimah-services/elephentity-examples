# elephentity-examples

Read [README.md](README.md) first — this file assumes it.

## Layout

Each top-level directory is one example, built and tested as a real product: its own
`composer.json`, its own `eleph.json`, its own generated tree, its own CI job. Nothing is
shared between them except this repository's `tools/`, `.docker/` and `.llms/`.

## Working in a repository holding more than one product

`tools/php` mounts the whole repository but runs the container's working directory
wherever you invoked it from, so always `cd` into the example first:

```bash
cd clog
../tools/php composer install
../tools/php composer ci
```

Running `./tools/php` from the repo root itself has nothing to build against — there is
no `composer.json` there by design.

## The generated tree is signed

`clog/generated/` is committed and every file carries a digest
(`GENERATED BY Elephentity — DO NOT EDIT`). Never hand-edit it. If a spec change means
the tree should differ, regenerate:

```bash
cd clog
../tools/php vendor/bin/eleph generate
```

and commit the diff. If `eleph generate --check` reports a divergence you did not cause
by editing the spec, **stop and find out why before regenerating over it** — a byte
changing here with no spec change usually means a builder or an adaptor moved out from
under this example, which is the exact class of bug this repository exists to catch.

## Before you commit anything that crosses a repository boundary

**[`.llms/cross-repo.md`](.llms/cross-repo.md) is the closed list of what crosses.** If
you changed something on it, open an issue on each repository it reaches, before or
with the push. [`.llms/README.md`](.llms/README.md) has the rule and
[`.llms/issue-template.md`](.llms/issue-template.md) the shape.
