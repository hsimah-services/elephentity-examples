# Contract surface

Only the changes below require cross-repository issues. Renaming internal methods or
editing source comments does not change a contract. Editing generated comments does:
their bytes contribute to file signatures.

## Source locations

- Compiler IR/codecs: `elephentity/packages/schema/src/Ir/` and `Wire/`.
- Rust orchestrator: `elephentity-codegen/rust/main.rs`.
- Each Rust builder: `rust/main.rs` for dispatch/version checks, `rust/ir.rs` for IR.
- PHP emitted names: `elephentity-codegen-php/rust/runtime.rs` and generator modules.
- WordPress manifests: `elephentity-codegen-wordpress/rust/storage.rs`,
  `registration.rs`, and `*-header.txt` templates.
- WPGraphQL manifests: `elephentity-codegen-wpgraphql/rust/manifest.rs`,
  `manifest-header.txt`, and `verify.php`.
- WordPress/WPGraphQL capabilities: each builder's `rust/provides.json`.
- PHP `src/` copies in generator repositories are test references, not production code.
  Keep them useful as independent oracles when evolving contracts deliberately.

## Compiler and protocol

| Change | Required consumers |
|---|---|
| Protocol version or envelope shape | Compiler/CLI, orchestrator, all standalone builders, and the in-repository memory builder |
| IR version or field shape/meaning | Compiler codec, orchestrator version gate, and each standalone builder's IR types/version gate |
| `describe` capabilities or payload shape | Compiler `Installed`/capability codecs and the affected builder; update orchestrator envelope handling only if its shape changes |
| Compiler request shape | CLI request construction and orchestrator decoding |
| `targets` output | CLI output-directory discovery |
| Required `eleph.json` keys | The component reading them, consuming projects, and setup documentation |

Schema and capabilities are opaque to the orchestrator. New IR or capability fields do
not require it to interpret their contents. The memory builder reads no IR fields;
it is affected by protocol changes, not entity-field additions.

Protocol and IR versions are independently declared. Coordinate incompatible updates:
a mismatch must fail the version gate instead of silently dropping semantics.

## Generated output and runtime

| Change | Required consumers |
|---|---|
| Generated bytes, including formatting | Regenerate and commit `elephentity-examples/clog/generated/` |
| Signature/header format, line count, or digest inputs | Regenerate every affected signed tree; update signature fixtures and protocol docs |
| PHP class-map shape | `elephentity/packages/cli/src/ClassMap.php` and generated-tree consumers |
| Runtime class names, constructors, or manifest shapes | Matching builder's emitted names/templates and Clog wiring/generated output |
| Runtime interfaces implemented by adaptors | Implementations in `elephentity-wordpress` and/or `elephentity-wpgraphql` |
| Driver naming or edge-placement rules | WordPress builder and runtime SQL naming/query interpretation |
| Packaged pattern or integration declaration | Compiler capabilities and consuming specs; regenerate if output changes |
| Generator installation/build requirements | Consumer setup/CI, including Clog |

The IR gate does not check PHP runtime manifest compatibility. Builders emit runtime
class names as strings; regenerate Clog, run static analysis and `eleph check`, and
exercise affected runtime paths.

## Runtime mirror

Edit `src/` and `tests/` in `elephentity/packages/runtime`, not in the mirror. The split
workflow copies only those directories on main pushes and tags the mirror on source
tags. It does not copy composer.json, dependencies, docs, or tooling. Update production
requirements in the mirror's composer.json manually when they change at the source.

## Independent internals

A builder's configuration interpretation, algorithms, and private helpers are local
until they change a listed contract. One builder's IR copy is not imported by another.
The TypeScript repository is currently a scaffold, not another protocol implementation.
